# 实现与验证

## 逐 Task 循环

对任务拆分中的每个 Task：

### Step 1 — 前置条件检查

| 条件类型 | 处理 |
|---|---|
| **必要条件**（缺了无法正确实现） | **停止该 Task**，告知用户缺少什么，不猜测、不跳过 |
| **可后补条件**（有合理默认或可之后补充） | 继续执行，将缺口写入“待办”列表 |

### Step 2 — 实现

按设计文档实现。**不扩大范围，不做设计未覆盖的“顺手优化”。**

### Step 3 — 自检（你定义的“验证逻辑”）

逐项检查，输出简短结论：

| # | 检查项 |
|---|---|
| 1 | 代码能正常运行，无基础语法错误导致无法启动 |
| 2 | 实现符合需求 |
| 3 | 无明显逻辑漏洞 |
| 4 | 符合常见代码规范和格式 |
| 5 | 足够优雅（无重复、命名清晰、职责单一） |

### Step 4 — 审查

- **简单模式**：以上自检清单即为审查记录，不启动独立审查。
- **完整模式**：将变更交给独立审查视角（可在同一 Skill 内以“审查者”角色执行），输出结构化审查结论，**不以“我觉得没问题”代替证据**。

### Step 5 — 测试

根据 `env-probe` 的结果：
- 已集成测试框架：生成或运行对应测试；
- 未集成：按 `references/java-testing.md` 或 `references/vue-testing.md` 中的推荐策略，生成测试建议或代码，标记为“待用户确认测试方案”。

## 输出

每个 Task 完成后，记录：自检结论 / 审查记录（完整模式）/ 测试结果 / 待办新增项。
